# دليل التسليم — SADDAM BARBER

خطوات تسليم الموقع للعميل خطوة بخطوة، من النشر لحد ما العميل يبقى قادر
يعدّل بنفسه من لوحة التحكم.

---

## 1) قرار مهم قبل أي حاجة: أنهي نسخة هتسلّمها؟

| | النسخة الكاملة (سيرفر + قاعدة بيانات) | النسخة الثابتة (GitHub Pages) |
| --- | --- | --- |
| لوحة التحكم `/admin` | ✅ موجودة | ❌ مش موجودة |
| العميل يعدّل بنفسه | ✅ من اللوحة | ❌ لازم مبرمج يعدّل الكود |
| نموذج الحجز | ✅ بيتسجّل في قاعدة البيانات + واتساب | واتساب بس |
| التكلفة | من مجاني لـ ~5$/شهر | مجاني |

> طالما العميل عايز يعدّل بنفسه → **لازم النسخة الكاملة**.
> نسخة GitHub Pages تنفع كنسخة عرض/احتياطية بس.

---

## 2) اختار مكان الاستضافة

### أ) Railway / Render / VPS ← **الأفضل هنا ✅**
سيرفر بقرص تخزين دائم، يعني **الصور اللي العميل يرفعها من اللوحة بتفضل موجودة**.

### ب) Vercel + قاعدة بيانات Neon
سريع ومجاني، بس ⚠️ نظام ملفات Vercel مؤقت → **رفع الصور من اللوحة مش هيشتغل**
(الصورة هتختفي بعد إعادة التشغيل). لو هتستخدم Vercel:
- خلّي العميل يستخدم **لينك صورة جاهز** بدل الرفع، أو
- قوللي أحوّل تخزين الصور لقاعدة البيانات / Vercel Blob (شغل بسيط).

---

## 3) خطوات النشر (Railway كمثال)

1. اعمل مشروع جديد من GitHub repo.
2. ضيف خدمة **PostgreSQL** من نفس المشروع (Railway بيديك `DATABASE_URL` جاهز).
3. في إعدادات الموقع (Variables) حط:

```bash
DATABASE_URL=postgresql://...        # من خدمة قاعدة البيانات
ADMIN_PASSWORD=كلمة-سر-قوية-للعميل
ADMIN_SECRET=نص-طويل-عشوائي
NODE_ENV=production
```

4. أوامر البناء والتشغيل:

```bash
Build:  npm ci && npx drizzle-kit push --force && npm run build
Start:  npm start
```

5. أول مرة بس، شغّل زرع البيانات (من Terminal بتاع الاستضافة):

```bash
npm run seed
```

> ⚠️ `npm run seed` بيمسح كل حاجة ويرجّع البيانات الافتراضية —
> **متشغلوش تاني بعد ما العميل يبدأ يعدّل**.

6. اربط الدومين بتاع العميل من إعدادات الاستضافة (مثال: `saddambarber.com`)،
   واتأكد إن SSL شغال (https).

7. اتأكد إن كل حاجة تمام:
   - `https://الدومين/` → الموقع ظاهر.
   - `https://الدومين/api/health` → `{"ok":true}` (معناها قاعدة البيانات متوصلة).
   - `https://الدومين/admin` → شاشة كلمة السر.

## 4) جهّز المحتوى قبل التسليم (من `/admin`)

- [ ] **إعدادات الموقع**: اسم الصالون، اللوجو، رقم التليفون، الواتساب،
      البريد الإلكتروني، العنوان، المواعيد، إنستجرام/فيسبوك/تيك توك.
- [ ] **الفروع**: العنوان والرقم والمواعيد و«الإحداثيات» (lat/lng) صح —
      دي اللي بتحدد مكان الدبوس على الخريطة.
- [ ] **الخدمات**: الأسعار الحقيقية المحدّثة + الصور.
- [ ] **العروض**: الساري منها بس، والباقي اعمله «إخفاء».
- [ ] **معرض الصور**: صور حقيقية من الصالون.
- [ ] امسح أي بيانات تجريبية.
- [ ] غيّر `ADMIN_PASSWORD` لكلمة سر قوية وسلّمها للعميل **بره الشات/الإيميل العام**.

---

## 5) النسخ الاحتياطي (مهم جداً)

كل المحتوى في قاعدة البيانات، فخد نسخة احتياطية دورية:

```bash
# نسخة احتياطية
pg_dump "$DATABASE_URL" > backup-$(date +%F).sql

# استرجاع
psql "$DATABASE_URL" < backup-2026-09-26.sql
```

أغلب الاستضافات (Railway / Render / Neon) عندها Backups تلقائية — فعّلها.
والصور المرفوعة موجودة في مجلد `public/uploads` (خدلها نسخة كمان).

---

## 6) اللي تسلّمه للعميل

1. **لينك الموقع** + **لينك لوحة التحكم** (`/admin`).
2. **كلمة سر اللوحة** (في رسالة خاصة).
3. ملف [`docs/دليل-العميل.md`](./دليل-العميل.md) — شرح مبسّط بالعربي إزاي يعدّل بنفسه.
4. بيانات الدخول للاستضافة وقاعدة البيانات (لو متفقين إنها تبقى باسمه).
5. جلسة تدريب 15 دقيقة: يغيّر سعر خدمة، يضيف عرض، يرفع صورة، يخفي عنصر.

---

## 7) بعد التسليم

- راقب `/api/health` (أي أداة uptime مجانية) علشان تعرف لو قاعدة البيانات وقعت.
- لو قاعدة البيانات وقعت، **الموقع مش بيفصل** — بيرجع تلقائياً للبيانات
  الافتراضية الموجودة في `src/data/`، بس التعديلات الجديدة مش هتظهر
  لحد ما ترجع.
- أي تعديل على الشكل/التصميم نفسه لسه محتاج مبرمج — المحتوى بس هو اللي
  بيتعدّل من اللوحة.
