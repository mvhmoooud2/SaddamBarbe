# SADDAM BARBER — موقع صالون صدام للحلاقة

موقع تعريفي كامل (عربي / RTL) لصالون حلاقة: خدمات، عروض بخصومات، معرض صور،
قسم «فروعنا» بخريطة لكل فرع، آراء العملاء، ونموذج حجز مواعيد.

- **النسخة الحيّة على GitHub Pages:** https://mvhmoooud2.github.io/SaddamBarbe/
  (نسخة ثابتة بالبيانات الأساسية، بدون قاعدة بيانات وبدون API)
- **النسخة الكاملة** (بقاعدة بيانات + حجز فعلي): تشتغل بـ Next.js + PostgreSQL.

---

## تشغيل الموقع محلياً

### الطريقة السريعة (بتجهّز كل حاجة لوحدها)

```bash
npm run dev:up
```

السكربت ده بيشتغل: تثبيت الحاجات → تجهيز PostgreSQL محلي → بناء الجداول وزرع البيانات →
تشغيل الموقع على <http://localhost:3000>

### الطريقة اليدوية

```bash
cp .env.example .env        # وعدّل DATABASE_URL حسب إعداداتك
npm install
npx drizzle-kit push --force   # بناء الجداول
npm run seed                   # زرع البيانات
npm run dev                    # http://localhost:3000
```

> لو قاعدة البيانات مش متاحة، الموقع **مش بيفصل** — بيشتغل تلقائياً بالبيانات
> الثابتة الموجودة في `src/data/seed-data.ts`.

## نشر نسخة GitHub Pages (النسخة الثابتة)

النشر بيحصل تلقائياً: أي دفع على فرع `main` بيشغّل
[workflow النشر](.github/workflows/deploy-pages.yml) اللي بيبني نسخة ثابتة ويرفعها على Pages.

للتجربة محلياً **بنفس مسار GitHub Pages** (مهم جداً):

```bash
npm run build:pages      # بينتج مجلد out/
npm run preview:static   # يعرضها على http://localhost:4000/SaddamBarbe/
```

### ⚠️ قاعدة مهمة

GitHub Pages بيخدم الموقع على `/<اسم-المستودع>` وليس على الجذر، والمستودع اسمه
`SaddamBarbe`، فالمسار هو **`/SaddamBarbe`**.

لازم `NEXT_PUBLIC_BASE_PATH` يساوي نفس المسار في بناء نسخة Pages
(الـ workflow بيظبطه تلقائياً). لو المسار غلط، ملفات CSS/JS والصور كلها بترجع 404
والصفحة تظهر بدون تصميم وبدون أي تفاعل.

نفس المتغير مستخدم في `next.config.ts` وفي `src/lib/base-path.ts` (دالة `asset()`)
علشان مسار الصفحة ومسار ملفات الصور يبقوا متطابقين دايماً.

### نسخة Pages بتشتغل إزاي؟

- مفيش قاعدة بيانات ومفيش API routes → الصفحة بتتبني بالبيانات الثابتة.
- نموذج الحجز بيحوّل الطلب لواتساب تلقائياً (زر «ابعت الحجز على واتساب»).

## قاعدة البيانات على Supabase + لوحة التحكم

دلوقتي تقدر تعدّل محتوى الموقع (عروض، خصومات، خدمات، أسعار، حلاقين، آراء، حجوزات)
من لوحة تحكم جاهزة على **`/admin`** من غير ما تلمس أي كود.

### 1) إنشاء المشروع على Supabase
1. ادخل [supabase.com](https://supabase.com) → **New project** واختار كلمة سر للداتابيز.
2. من **SQL Editor → New query**: الصق محتوى `supabase/schema.sql` واضغط **Run** (بيعمل الجداول + الحماية).
3. نفس الخطوة تاني بمحتوى `supabase/seed.sql` (بيحط بيانات الموقع الحالية).
   - لو غيّرت `src/data/seed-data.ts` تقدر تولّد الملف تاني بـ: `npm run supabase:seed-sql`

### 2) ربط الموقع بالداتابيز
من Supabase: **Project Settings → Database → Connection string → URI**، وحط الرابط في `.env`:

```bash
DATABASE_URL=postgresql://postgres.xxxx:كلمة_السر@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
ADMIN_PASSWORD=كلمة-سر-لوحة-التحكم
```

الـ SSL بيتفعّل تلقائياً لأي رابط مش محلي، فمش محتاج أي إعداد زيادة.
نفس المتغيّرين لازم يتحطوا في إعدادات الاستضافة (Vercel / Railway / أي سيرفر).

### 3) استخدام لوحة التحكم
افتح `http://localhost:3000/admin` (أو `دومينك/admin`) → ادخل بكلمة السر (`ADMIN_PASSWORD`)، وتقدر:

- **العروض والخصومات**: إضافة عرض جديد بالسعر قبل/بعد الخصم ولافتة «خصم 30%» وتاريخ انتهاء وتفاصيل.
- **الخدمات والأسعار**: تعديل أي سعر أو مدة أو وصف، أو إضافة خدمة جديدة.
- **الحلاقين** و**آراء العملاء**: إضافة/تعديل/حذف.
- **الحجوزات**: متابعة الحجوزات وتغيير حالتها (`pending` / `confirmed` / `done` / `cancelled`).
- **إعدادات الموقع**: قيم عامة (واتساب، تليفون، عنوان، مواعيد) في جدول `site_settings`.
- زرار **ظاهر/مخفي** بيخفي أي عنصر من الموقع فوراً من غير حذف.

أي تعديل بيظهر على الموقع على طول لأن الصفحات بتقرأ من نفس الجداول.
وكمان تقدر تعدّل من Supabase نفسه عن طريق **Table Editor**.

> ملاحظة: نسخة GitHub Pages الثابتة مالهاش سيرفر، فلوحة التحكم و الـ API
> مش بيتصدّروا معاها (السكربت بيستثنيهم تلقائياً) — اللوحة بتشتغل على النسخة
> المستضافة بسيرفر (`npm run build` + `npm start`).

## تعديل بيانات الموقع

| إيه اللي عايز تغيّره | الملف |
| --- | --- |
| رقم الهاتف / الواتساب / العنوان / مواعيد العمل / السوشيال | `src/data/site-config.ts` |
| فروع الصالون (العناوين + أرقام التليفون + الإحداثيات + المواعيد) | `src/data/branches.ts` |
| الخدمات، العروض، الفريق، آراء العملاء | `src/data/seed-data.ts` (وبعدها `npm run seed` للنسخة بقاعدة البيانات) |
| صور الموقع | `public/images/` |
| الألوان والهوية | `src/app/globals.css` + الألوان داخل المكوّنات `text-[#c9a227]` |

> النصوص والأرقام الحالية (العنوان ورقم الموبايل والسوشيال) **بيانات مؤقتة** —
> عدّلها من `src/data/site-config.ts` قبل ما تعرض الموقع على العملاء.
>
> نفس الكلام على بيانات الفروع في `src/data/branches.ts`: كل فرع له اسمه وعنوانه
> ورقمه ومواعيده وإحداثياته (`lat`/`lng`)، والإحداثيات هي اللي بتحدد مركز الخريطة
> ولينك الاتجاهات. لو الإحداثيات مش متاحة، الخريطة بتدور على `mapQuery` أو العنوان.

## أوامر مفيدة

```bash
npm run dev            # تشغيل بيئة التطوير
npm run build          # بناء نسخة الإنتاج (سيرفر + قاعدة بيانات)
npm run build:pages    # بناء نسخة GitHub Pages الثابتة
npm run preview:static # معاينة النسخة الثابتة بنفس مسار Pages
npm run lint           # فحص الكود
npm run typecheck      # فحص الأنواع
npm run seed           # إعادة زرع بيانات قاعدة البيانات
npm run supabase:seed-sql  # توليد supabase/seed.sql من بيانات الموقع
```
